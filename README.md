# Практическая работа №3. Процессы в Linux

Среда: Windows 11 + WSL2, Ubuntu 24.04, Python 3.12.

## Файлы
- `ptree.py` - дерево процессов текущего пользователя по /proc (PID, состояние, RSS)
- `runner.py` - N детей через fork+exec, коды возврата и время работы
- `zombie.py`, `orphan.py` - воспроизведение зомби и сироты
- `cow.py` - copy-on-write после fork

## Запуск
- `python3 ptree.py`
- `python3 runner.py 3 sleep 1`
- `python3 zombie.py`
- `python3 orphan.py`
- `python3 cow.py`

Реальные выводы программ приведены в разделе "Выводы программ" в конце файла.

## Зомби
Ребёнок завершился, а родитель ещё не вызвал `wait`. Запись о ребёнке остаётся в таблице
процессов в состоянии `Z` (в выводе `STAT=Z+`) и исчезает после `waitpid`.
Вывод - в `zombie_output.txt`.

## Сирота
Родитель завершается раньше ребёнка. Ядро передаёт сироту другому процессу: ближайшему
предку-subreaper, а если такого нет - процессу с PID 1. Вывод - в `orphan_output.txt`,
вывод `ps` по усыновителям - в `adopter_ps.txt`.

**Кто усыновляет сироту:** в моей системе PID 1 - это `systemd` (`/sbin/init`), но сироту
усыновил не он, а процесс `/init` с PID 1115 (в `ps` он показан как `Relay(1116)`) -
служебный процесс WSL, предок моей оболочки bash. Он ближе к сироте, чем PID 1, поэтому
сирота перешла к нему. `systemd --user` (PID 1195) сироту не усыновил.

## Copy-on-write
Родитель создаёт список из 3 000 000 элементов, затем делает fork. Ребёнок меняет
каждый элемент списка. Вывод - в `cow_output.txt`.

Сразу после fork у ребёнка `Private_Dirty` = 0.6 MB, а `Pss` примерно вдвое меньше
`Rss`: страницы общие с родителем, память не копировалась. После изменения списка
`Private_Dirty` и `Pss` ребёнка выросли до ~115-118 MB: ядро скопировало страницы при
первой записи в них. Значение `RSS` почти не изменилось (122.4 -> 122.8 MB), потому что
RSS считает и общие, и приватные страницы, и по одному RSS копирование не видно.
Родитель при этом не менялся. Итог: память после fork копируется лениво (copy-on-write).

## Проверка отсутствия зомби и фоновых процессов
После запуска всех скриптов команды
`ps -eo pid,ppid,stat,comm | awk '$3 ~ /Z/'` и
`ps -u $USER -o pid,ppid,stat,comm | grep -E 'python3|sleep'` ничего не вывели.

## Контрольные вопросы
1. **Почему fork возвращает два разных значения?**
   После fork существуют два процесса с одним и тем же кодом, и каждый должен понять,
   кто он. В родителе fork возвращает PID ребёнка (иначе родитель не узнает, кого ждать),
   в ребёнке - 0 (родителя он узнаёт через getppid). При ошибке возвращается -1.
2. **Что изменится, если вызвать exec без fork?**
   Текущий процесс заменит свой образ программой из exec: PID останется тем же, а код
   будет другим. Код после exec не выполнится, и вызывающая программа перестанет
   существовать - после завершения запущенной команды продолжать будет нечему.

## Типичные ошибки (учтено)
- В ветке ребёнка вызывается `os._exit`, поэтому обе ветки не выполняют один код.
- Родитель ждёт всех детей (`wait`/`waitpid`), поэтому зомби не остаются.
- В `orphan.py` главный процесс ждёт сироту, чтобы вывод не "съел" приглашение оболочки.
